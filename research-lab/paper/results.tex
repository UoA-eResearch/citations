\subsection{Were plans committed before outcomes?}
\label{sec:prereg}

\paragraph{Commit order.} Git shows the plan committed strictly before any results file or report in
\PreregPassStrict{} of \StudiesTotal{} studies. Across those \PreregPassN{}, the median gap to the first output was
\PreregMedianHours{} hours (range \PreregMinHours{}--\PreregMaxHours{} h); \PreregUnderHour{} plans came less than an
hour before their first output.

\paragraph{Push records.} GitHub's server-side push events, archived in \path{audit/}, back up the commit timestamps.
All \PushUnderMinute{} plan commits reached GitHub within \PushMaxLagSec{} seconds of their commit time, and the
\PushStrictN{} plans committed strictly first were all pushed before their first output.

\paragraph{A history rewrite.} The public history was rewritten once. On 1 October 2026 the lab owner noticed that
early commits were authored by the machine's default git identity and asked for them to be attributed to the agent.
The author identity of \RewrittenCommits{} commits (the four GWTC-4 commits and the bioinformatics plan) was rewritten
with \texttt{git filter-branch}, and the branch was force-pushed. Tree, timestamps and messages were unchanged in all
five.

\path{audit/A_rewrite_map.csv} lists each original commit ID, its current ID and its tree hash. The original commit
IDs also appear in the archived push events, and the original commits are kept on a local branch. The push lags above
match each rewritten plan commit through its original. A force-push of public history is exactly the kind of event
that commit timestamps alone cannot rule out. This one was benign, and it is disclosed here.

\paragraph{The four same-commit cases.} In the other \PreregSameCommit{} studies the plan and some results files arrived
in a single commit. Both coders classified every file in those commits.
\begin{itemize}
\item \textbf{Three contained only pre-outcome material:} pre-period tables and the hash of a sealed post-period file
(speed limits), a catchment inventory (wastewater), and a data-coverage table (FluSight).
\item \textbf{The fourth was the first study (GWTC-4).} Its plan entered git in the same commit as the full results,
including the verdict.
\end{itemize}
The first study's plan file did exist earlier: the agent's private session record shows it, with the committed
content, on 2 September 2026. That record is not public or externally timestamped, so it is weaker evidence than the
commit history. The report of that study described itself as preregistered, and it now carries a correction.

\paragraph{Overall.} Counting pre-outcome material as compliant, plans demonstrably came first in
\PreregPassClassified{} of \StudiesTotal{} studies (\CIPreregClassified{}). No plan was edited after its first commit.
This shows only that plans were \emph{committed} first. It cannot show that they were written before the data were
explored, which is what the disclosure sections and, where used, sealing are for.

\subsection{Which safeguards did the plans use?}
\label{sec:inventory}

\begin{itemize}
\item \textbf{Applied consistently.} Every plan stated a decision rule. \InvDisclosure{} disclosed what had already
been seen (and \InvDisclosurePartial{} partially; an earlier text search found explicit sections in only 13, because it
looked for specific headings). \InvDataOpen{} used only data that are open without registration.
\item \textbf{Applied unevenly.} \InvValidation{} plans required validation before the primary analysis,
\InvValidationPartial{} did so partially and 2 did not. Of the 8 plans with several primary tests, \InvMultiplicityYes{}
addressed multiplicity. These codes come from a single coder and carry no reliability estimate.
\item \textbf{Power.} Only one plan (speed limits) stated a minimum detectable effect before results, and one more did
so partially. Two studies record both an assumed effect and a detectable one:
  \begin{itemize}
  \item the speed-limit study hypothesised a crash rate ratio of 1.10 but could detect only 1.33;
  \item the wastewater study assumed a ratio of 0.85 and, after review, computed a detectable ratio of 0.71.
  \end{itemize}
Both studies were underpowered for the effect they set out to detect, and both ended \emph{Inconclusive}.
\item \textbf{Keeping outcomes out of reach.} This was done in only \InvBlindStrong{} studies: two sealed (speed
limits, quantum) and one prospective (City Rail Link). \InvBlindPartial{} more did so partially. In the other
\InvBlindNone{}, the outcome data were public and the disclosure section is the only safeguard. Only one
\emph{decided} study had its outcomes sealed.
\end{itemize}

\subsection{Deviations}

The coders identified 141 and 142 deviation entries across all 19 studies. The difference is whether one review
paragraph in GWTC-4 counts as a separate entry, and we kept coder A's segmentation. GWTC-4's log has 39 numbered
headers plus ``outcome'' sub-headers and a final audit. Both coders folded the sub-headers into their parent entry,
split the combined header D29b--d into three entries, and coded the final audit as one entry. That gives 36 entries (37 for coder~B, who also counted the review paragraph
separately). Following the audit plan, the
analysis covers the \DevN{} entries in the \StudiesReported{} reported studies.

\paragraph{Agreement.} Agreement was high:
\begin{itemize}
\item category $\kappa=\KappaCategory{}$;
\item trigger $\kappa=\KappaTrigger{}$;
\item timing $\kappa=\KappaTiming{}$;
\item verdict relevance $\kappa=\KappaVerdictRelevance{}$.
\end{itemize}
Disagreements were settled with three fixed rules: category follows the cause; verdict relevance takes the cautious
side; timing is ``unclear'' if either coder said so. Each decision is logged.

\paragraph{Categories and triggers.} The categories were:
\begin{itemize}
\item added secondary analyses: \DevCFive{};
\item clarifications: \DevCSeven{};
\item bug or numerical fixes: \DevCOne{};
\item environment and logistics: \DevCSix{};
\item changes to the primary specification: \DevCThree{};
\item data problems: \DevCTwo{};
\item withdrawn or corrected claims: \DevCEight{};
\item decision-rule changes: \DevCFour{} (Figure~\ref{fig:dev}).
\end{itemize}
\DevAfter{} entries were made after the primary outcome was seen. \DevAfterReviewer{} of these were requested by the
reviewer, which necessarily comes after the results, and \DevAfterNotReviewer{} were initiated by the agent or by a
validation check.

\paragraph{Verdict relevance.} \DevRelevant{} entries (\CIDevRelevant{}) could plausibly have changed the verdict, and
\DevRelevantAfter{} of them were made after the outcome was seen. Of those:
\begin{itemize}
\item \DevRelevantAfterValRev{} were triggered by validation or review, mostly corrections of errors;
\item \DevRelevantAfterExec{} were the agent's own changes after seeing the outcome.
\end{itemize}
The first study accounts for \DevGWTC{} of the \DevN{} entries and \DevRelevantAfterGWTC{} of the \DevRelevantAfter{}
verdict-relevant post-outcome ones. It also accounts for most of the agent's own post-outcome changes (entries
\GWTCExecAfterIDs{}): a primary statistic redefined, a statistic abandoned, a decision rule chosen after the real-data
values were seen, and a recalibration. Without the first study:
\begin{itemize}
\item \DevNNoG{} entries remain;
\item \DevRelevantNoG{} are verdict-relevant (\CIDevRelevantNoG{});
\item \DevRelevantAfterNoG{} are verdict-relevant and post-outcome;
\item \DevRelevantAfterExecNoG{} of those were the agent's own changes: a corrected claim and a numerical guard.
\end{itemize}

\paragraph{Decision rules.} Two decision rules were changed:
\begin{itemize}
\item GWTC-4's, after the outcome was seen; the study's own final audit judged it post hoc;
\item the City Rail Link study's, after review but before any outcome data existed. A further City Rail Link entry
moved a threshold and was coded as a specification change.
\end{itemize}

\paragraph{Comparison with human studies.} In human preregistered studies, undisclosed deviations are common: 9 of 27
early \emph{Psychological Science} studies disclosed none of theirs \citep{claesen2021dream}. Here every deviation the
agent made is, by construction, in a public log. The audit cannot detect deviations that were never logged.

\subsection{What independent review changed}
\label{sec:review}

\paragraph{Recommendations.} Every review asked for changes:
\begin{itemize}
\item \ReviewFixFirst{} said ``fix first'';
\item \ReviewRefutedRec{} (the first study's methodology review) said ``refuted'';
\item \ReviewPublishEdits{} said ``publish with edits''.
\end{itemize}
A confirmation pass followed in \ReviewConfAmongFix{} of the \ReviewFixOrRefuted{} studies whose review demanded fixes.

\paragraph{Issues raised.} The coders agreed on the exact number of issues per review only \ReviewIssuesExactAgree{}
of the time, so we give both totals: \ReviewIssuesTotal{} and \ReviewIssuesTotalB{}. By category:
\begin{itemize}
\item analysis or model errors: \ReviewRTwo{} and \ReviewRTwoB{};
\item computational errors: \ReviewROne{} and \ReviewROneB{};
\item overclaiming: \ReviewRFour{} and \ReviewRFourB{};
\item missing analyses: \ReviewRFive{} and \ReviewRFiveB{};
\item documentation: \ReviewRSix{} and \ReviewRSixB{};
\item leakage or blinding: \ReviewRThree{} each.
\end{itemize}

\paragraph{What changed.} No study committed a pre-review draft, so what review changed is known only from the agent's
own deviation logs and the reports' accounts of their reviews. On that evidence:
\begin{itemize}
\item \textbf{Headlines.} Review changed the headline estimate in \CHeadlineA{} studies according to coder A,
\CHeadlineB{} according to coder B, and \CHeadlineEither{} according to either coder; we adjudicated \ReviewHeadlineChanged{}.
\item \textbf{Verdicts.} Review changed the verdict in \CVerdictA{} (A), \CVerdictB{} (B) or \CVerdictEither{}
(either); we adjudicated \ReviewVerdictChanged{}.
\end{itemize}
These measure-C adjudications followed no rule set in advance. In each case the adjudicated count is the lower one,
and we report all three counts for that reason.

The clearest cases, each documented in the run directory, were these:
\begin{itemize}
\item \textbf{Seismology:} the reviewer found a local optimum, and the Norcia recovery fraction moved from 0.51 to
0.88. The pre-review value is in \path{results/tables/primary_round1.csv}.
\item \textbf{GWTC-4:} the verdict went from ``confirmed'', recorded in the commit message of the plan commit, to
``indeterminate''. Its headline false-positive rate was replaced: a different statistic, not a re-estimate.
\item \textbf{Citation-context study:} the verdict went from a refutation to ``uninformative'' after its positive
control failed.
\end{itemize}

\subsection{Are the numbers in reports accurate?}

\paragraph{Direct verification.} Both coders independently checked a seeded random sample of \VerifyN{} substantive
numbers, 7 from each report, locating the specific source of each.
\begin{itemize}
\item \textbf{Consistent with their source:} \VerifyOKA{} (coder A) and \VerifyOKB{} (coder B); \VerifyOKBoth{} by
both coders (\VerifyCIOKBoth{}; agreement on the class $\kappa=\VerifyKappa{}$). Sources ranged from a results cell to a recomputation from the data or a design
parameter.
\item \textbf{Inconsistent:} \VerifyFourEither{}. Both were flagged by coder~B; coder~A had judged them to sit on a
rounding boundary. Recomputation confirmed both as rounding errors of one unit in the last printed digit, caused by
rounding twice: 0.9149 printed as 0.92, and 0.35497 printed as 0.36. The first also appears in a deviation entry.
\item \textbf{Not verifiable:} \VerifyFiveEither{} could not be verified by at least one coder.
\end{itemize}
A coder also found a phrase in one report that described a share of boardings as if it were a share of routes. Every
confirmed error has been corrected in the report and logged in the study's deviation file.

\paragraph{Untraced sample.} An earlier sample of \UntracedN{} numbers that automated matching had failed to trace
gave a similar picture: no number inconsistent with the results, and three untraceable. All three untraceable numbers
are figures the reviewer computed in scratch code that was never saved. Outside that sample, a coder found a third
rounding error by the same mechanism (coder~A, Fable~5.1), now corrected. Coder~B (Opus~5.5) found the matcher bug
logged as audit deviation A8. The sample is lopsided: \SampleReportsTen{} reports contributed
10 numbers each, out of \SampleReports{} reports in all.

\paragraph{Automated matching does not work.} We first tried to trace report numbers automatically. The method
searches a study's \path{results/} files for any value within rounding of each printed number.
\begin{itemize}
\item It matched \TraceROwn{} of substantive numbers. Shifting each number by 3--7 units in its last printed digit
and searching the same files still matched \TraceRChance{} (Figure~\ref{fig:numbers}).
\item At three significant figures the rates were \TraceROwnThree{} and \TraceRChanceThree{}.
\end{itemize}
Result files contain so many nearby values that a match carries little information, and a wrong number can match by
chance. Earlier controls that matched against other studies' files understated this. Tracing a claim needs a pointer
to a specific cell, not a search for a matching value.

What the automated pass did reveal is \UntracedFivePlus{} untraced numbers with five or more significant figures.
\UntracedFivePlusTopN{} of them are sample sizes from one study (bioinformatics) that appear nowhere in its results
files.

\subsection{Scout estimates against outcomes}

\paragraph{Effort.} The scouts estimated a median of \ScoutDaysMedian{} days of wall time per study (\ScoutDaysTotal{}
days in total).
\begin{itemize}
\item \textbf{The first study} took far longer than estimated. Its transcript activity spans \GWTCSpanDays{} days
against an estimate of 3--6, with interruptions.
\item \textbf{The later studies} took far less. The \ReportsAfterFirst{} later reports appeared within
\CalendarBulkDays{} days, with several running in parallel.
\end{itemize}
Per-study effort cannot be measured reliably, because commits were made in bursts and transcripts rarely name the study
they concern. A transcript-based estimate gives \EffortActiveHoursTotal{} active hours across all studies, and we do
not rely on it.

\paragraph{Lead scores.} Every executed lead had a value score of \ValueMin{} or \ValueMax{} and a cost score between
\CostMin{} and \CostMax{}. With so little variation, nothing can yet be said about whether the scores predict verdicts.
