# Preregistration: do self-play provers drift toward vacuous conjectures?

Lead: `formal-math-selfplay-vacuity-drift` (research-lab/leads.json). Written 2026-10-05 and committed to git before any
vacuity check has been run on any corpus.

## What has been seen before writing (disclosure)

**STP corpus metadata.** The STP_Lean_0320 corpus (kfdong/STP_Lean_0320, 3,262,558 rows) was downloaded. Its row
counts by iteration and tag were tabulated (`results/tables/stp_counts.csv`, regenerated by `code/sample.py`):

- 2,751,225 conjecture rows, in iterations 1-23 and 25-47;
- 404,412 statement rows (LeanWorkbook), in iterations 0-47;

do from iteration 1 (15k). STP's README states that self-play (Stage 2) was periodically restarted from a re-trained
checkpoint (Stage 3). The corpus is therefore two self-play phases: rounds 0-23 and rounds 24-47.

has the hypothesis `[0, 3, 6, 9, 12, 15, 18].count n = 2`, which looks impossible because the list has no repeats. Its
original proof re-verified in our Lean REPL. No vacuity check (goal swap or automation) has been run on it or on any
other row.

**Environment.** STP's own Lean setup was reproduced:

## 1. Question

STP (Dong & Ma 2025) trains a prover by having it invent conjectures and prove them, and keeps the proved conjectures
as training data. A conjecture whose hypotheses contradict each other is "proved" without real mathematics.

Does the share of such vacuous conjectures grow as self-play continues? How common are they in the main open
prover-training corpora?

## 2. Units, populations and sample

The unit is a corpus row: one statement with one released proof.

**Conjecture rows (primary).** For each of the 46 conjecture iterations, rows are drawn uniformly without replacement
(seed 20261005) and placed in a random order within the iteration.

- **Primary windows.** Iterations 1-9 and 38-47 always get the first 2,000 rows (38,000 in total). Iteration 0 has no
  conjectures, so the plan's "iterations 0-9" window is 1-9 in practice.
- **Other iterations.** These get the first 2,000 rows if the timing pilot (section 6) projects at most 72 h for the
  whole STP sample on 12 workers. Otherwise they get the first 1,000. Because the order is random, the first 1,000 are a
  random subsample of the 2,000, and the choice does not depend on any vacuity outcome.

**Statement rows (control).** 200 per iteration, 0-47, giving 9,600 rows. These are proofs of a fixed pool of
LeanWorkbook statements.

**Other corpora (secondary).** Each is drawn uniformly at random:

| Corpus | Sample |
|---|---|
| Goedel-LM/Lean-workbook-proofs | 5,000 rows |
| Goedel-LM/SFT_dataset_v2 | 10,000 rows |
| deepseek-ai/DeepSeek-Prover-V1 | 5,000 rows, checked under Lean 4.9; reported only if at least 50% re-verify |
| AI-MO/NuminaMath-LEAN (formal_proof) | 10,000 rows, under its own Lean 4.15 toolchain, only if that toolchain is working within one working day; otherwise reported as not run |

## 3. Pipeline (per row)

1. **Parse.** Find the last `theorem`/`lemma` in the prompt and rename it to a fresh name. Split it at the first colon
   at bracket depth 0 after the name into the binders B and the conclusion C, ending at the final `:=`.
2. **Re-verify.** Re-verify the released proof under the corpus header (maxHeartbeats 0, 100 s wall-clock limit). Rows
   that do not re-verify are excluded from the denominators, and their rate is reported per iteration.
3. **Split check.** `example : ∀ B, C := <renamed original>` must compile. Rows that fail are excluded and counted. This
   guards against a parser that drops or moves a hypothesis.
4. **Vacuity certificates.** A row is **certified vacuous** if either (a) or (b) produces a proof of False from the
   hypotheses that compiles without errors, contains no `sorry`, and whose `#print axioms` lists only `propext`,
   `Classical.choice` and `Quot.sound` (so `sorryAx` and `native_decide`'s `Lean.ofReduceBool` are rejected).
   Compiling in the REPL adds the declaration to the environment, so the Lean kernel checks it.
   - **(a) Goal swap.** `theorem v B : False := by <released proof>` (maxHeartbeats 0, 100 s).
   - **(b) Automation.** `theorem v B : False := by <t>`, each tactic run separately with maxHeartbeats 100,000 and a
     30 s limit, stopping at the first success. The tactics, in order, are `omega`, `linarith`, `norm_num at *`,
     `simp_all`, `nlinarith`, `aesop`, and `decide` applied to `∀ B, False`. `grind`, listed in the lead, does not
     exist in Lean 4.9 mathlib, so it is not used.
5. **Triviality (secondary, primary-window rows only).** `theorem t B : C := by intros; clear * -; first | norm_num |
   simp | omega | linarith | nlinarith | positivity`, with maxHeartbeats 100,000. This counts conclusions that hold
   with all hypotheses discarded.

The method and the axioms of every certificate are recorded. Automation gives only a lower bound on true vacuity,
because hard contradictions are missed.

## 4. Primary test and decision rule

V = 1 if the row is certified vacuous, among rows that re-verify and pass the split check.

**Estimates.** p_E is the vacuity rate for iterations 1-9 and p_L for 38-47. Each is weighted by population, using
iteration strata with weights N_h / N_window, where N_h is the iteration's total conjecture-row count. Its variance is
Σ W_h² p̂_h(1 − p̂_h)/n_h. RR = p_L / p_E, with a 95% CI from the delta method on log RR.

| Verdict | Condition |
|---|---|
| **Supported** | RR ≥ 2 and a one-sided stratified two-proportion z-test of H0: p_L ≤ p_E gives p < 0.01. |
| **Refuted** | The upper end of the 95% CI for RR is below 2: a doubling is ruled out. |
| **Inconclusive** | Anything else, including fewer than 10 certified vacuous rows across both windows. In that case Wilson upper bounds are reported, and the result is read as "STP's filters suppress certifiable vacuity". |

**Statement-level analysis.** The same statement can appear in several rows with different proofs. The primary analysis
is repeated at statement level, where a statement counts as vacuous if any of its sampled rows is certified. If the two
verdicts differ, the disagreement is reported in the report's opening section.

## 5. Secondary analyses (all labelled secondary)

1. **Trend.** Per-iteration rates with Wilson CIs. Spearman ρ against iteration over all 46 conjecture iterations, and
   within each phase (1-23, 25-47).
2. **Within-phase and across-phase contrasts.** Each is a rate ratio with a 95% CI:
   - phase 1, late (14-23) vs early (1-9);
   - phase 2, late (38-47) vs early (25-33);
   - phase 2 vs phase 1, overall.
   The primary contrast spans a restart, so these separate drift within a self-play run from differences between runs.
3. **Statement-tag control.** Rate by iteration for statement rows.
4. **By certificate method.** Contribution of (a) vs (b), and the triviality rate.
5. **STP weight.** Logistic regression of V on the row's STP weight.
6. **Prevalence in other corpora.** For NuminaMath-LEAN, if run, the relation between vacuity and RL win_rate.
7. **Causes.** 100 randomly chosen certified-vacuous rows are hand-categorised by cause: natural-number subtraction or
   division, contradictory numeric constraints, a hypothesis that is an impossible fact, ZMod or Fin totality, or other.

## 6. Validation and pilot (before the main run, after this commit)

**Control statements.** The pipeline must:

- certify at least 18 of 20 hand-written vacuous control statements;
- certify 0 of 20 satisfiable controls (by soundness, any positive here can only be a parser or pipeline bug);
- pass the split check on all 40.

**Timing pilot.** A pilot on 300 conjecture rows not in the main sample measures throughput, the re-verification rate
and the split-check rate. It prints only those quantities. Its vacuity outcomes are written to a file that is not read
before the main analysis, and those rows are never analysed.

  non-certificates) and the statistics before any verdict.
